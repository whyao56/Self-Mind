# 内容优化方法论 · 概括版

决定一篇笔记怎么处理的时候看这页。要照着做，翻 [[内容优化方法论-详尽版]]。
这套东西是怎么想出来的，在 [[内容分型优化方法论-全流程报告]] 里。

## 什么时候用

三个条件都满足才用：笔记是我自己写的，里面有我的观察和判断；已经有正文了，不是空壳也不是只有一条链接；愿意先拿十来篇试试，格式定下来再往下推。

## 什么时候别用

- 笔记还没成形，先记着。空壳优化完还是空壳
- 索引页、军师台账这些是脚本生成的，改了下次重跑就没了
- 只是想调整主题分类，那是归类的事，跟这里无关
- 通篇只有一句话没有观点，先放着

判断标准就一条：它将来会不会被查、被做、被想、被练用到。会用到就适用，永远只是存着就不适用。

## 原理

不按主题分，按这篇将来怎么被调用分。

同样是讲睡眠的：拿来查，压成一句结论就够了；拿来做，比如怎么改善睡眠环境，就得写成能照着做的步骤。主题一样，处理方式不一样。

## 分四型

查型在 `仓库区/知识`，300 篇。追加三样：一句结论、什么时候用得上、我原来可能没看懂的地方。

做型在 `仓库区/手艺`，87 篇。追加四样：解决什么问题、动手前要有什么、哪里最容易失效、我到底试过没有。这一类会过期，半年后按钮位置改了、服务下架了，照着做就是白折腾，所以最急。

想型是日志和随笔，18 篇。逐日做深度整合，做法已经定了。

练型是书、语言、提示词，20 篇。追加问题、答案要点、一个能记住的画面。

军师台账和三十来个索引不优化，只维护。

顺序：做 87 → 查 300 → 想 18 → 报告 37 → 练 20。

## 追加块长什么样

只在笔记末尾加，原文一个字不动。每条用 @@@ 隔开，方便程序读。

查型：

```
@@@ <文件名>
结论：<一句话，脱离原视频也能读懂>
场景：<我在做什么的时候会用上> / <另一个场景>
补漏：<补什么 或 无>
@@@
```

做型：

```
@@@ <文件名>
解决什么：<一句话>
前置条件：<软件版本、账号、权限、系统环境；原文没写就写「原文未写」>
失效风险：<最可能随时间失效的地方，至少一条>
验证状态：<已验证 <日期> / 未验证>
@@@
```

练型：

```
@@@ <文件名>
问题：<能拿来考自己的问题>
答案要点：<三句以内>
锚点：<一个画面、比喻或者例句>
@@@
```

## 七步

1. 分批。每批 10 篇，按领域切，不跨领域混批
2. 选提示词。一次只跑一种类型，提示词在 [[笔记内容优化-提示词包]]
3. 出追加块。模型只给块，不重写原文
4. 校验。比对原来的标签、BV 号、图片引用，一样都不能丢
5. 追加到笔记末尾，frontmatter 里加一行 `整理: <日期>`
6. 抽检。每批自己看两篇，跑偏了就停下来改提示词
7. 提交。每批一次 commit

## 别做的事

1. 不改原文，只往后加
2. 不写「这条笔记是为了…」「将来失忆了可以看」这种话
3. 标签直接写短语，不写 `#内核/xxx` 这样的前缀
4. 每批都校验
5. 每批都提交
6. 台账和索引只读

## 例子 · 查型

拿 `仓库区/知识/军事与战争/FPV无人机视角下的战场.md`。原文 300 字，讲两个士兵撞上一架 FPV 无人机的瞬间。

模型给出的追加块：

```
@@@ 仓库区/知识/军事与战争/FPV无人机视角下的战场.md
结论：真正的绝望不是喊叫，是身体先反应、表情还没来得及跟上。
场景：写人物濒死的段落 / 分辨「表演性恐惧」和真实恐惧 / 分析战场影像
补漏：FPV 是「穿越机」第一人称视角，画面抖动大、速度快——最后那帧定格是偶然拍到的，不是刻意给的特写。
@@@
```

贴到笔记末尾之后是这样，原文一个字没动：

```
原来人在绝望时，真的会嘴角上扬。

Tags: #FPV无人机 #战争 #绝望 #人性 #瞬间

> 结论：真正的绝望不是喊叫，是身体先反应、表情还没来得及跟上。
> 场景：写人物濒死的段落 / 分辨「表演性恐惧」和真实恐惧 / 分析战场影像
> 补漏：FPV 是「穿越机」第一人称视角，画面抖动大、速度快——最后那帧定格
>       是偶然拍到的，不是刻意给的特写。
```

以后再想起这条，读那三行就够了。

七步全走一遍是什么样，连校验脚本和提交，在 [[内容优化方法论-详尽版]]。
