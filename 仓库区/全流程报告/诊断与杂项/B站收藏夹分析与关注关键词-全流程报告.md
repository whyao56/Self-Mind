## 四、写法与生效

`~/.dsh/bili-duty/config.json`：

```json
"keywords": ["认知科学", "学习方法", "编程教程", "DeepSeek Harness", "AI Agent",
             "Windows技巧", "数学科普", "物理科普", "时政分析", "军事历史",
             "恋爱心理", "健身康复", "地理科普"]
```

原文件备份在 `C:\Users\HP\WorkBuddy\2026-10-17-14-49-00\config.json.bak-before-keywords`。

插件的 `cfg` 是在插件初始化时读一次（`index.js` 第 168 行），之后一直用内存里那份，
所以改文件不会立刻反映到设置页，要重启 DSH。

设置页的输入框绑的是本地草稿，页面每 5 秒轮询 `/status`。
重启前如果先在设置页点「保存」，会把内存里那份空的关键词写回文件，等于覆盖掉这次的修改。

## 六、技术备注

在这台机器的 WorkBuddy 沙箱里跑 `~/.dsh/bili-duty/.venv/Scripts/python.exe` 会直接退出，
报 `Cannot read '...\.venv\pyvenv.cfg'`，退出码 107。同一个 venv 由 DSH 进程调用时正常
（18:43 的挂载日志、抓取都能跑），所以不是 venv 坏了，是沙箱拦了 launcher 读配置。

绕开的办法：用系统 Python 3.11，把 `PYTHONPATH` 指到 venv 的 `site-packages`：

```bash
PYTHONPATH="C:/Users/HP/.dsh/bili-duty/.venv/Lib/site-packages" \
  "E:/Python311/python.exe" bili_fav_crawl2.py
```

抓取脚本 `bili_fav_crawl2.py` 留在工作区，换 `TARGETS` 里的 media_id 就能抓别的夹。
