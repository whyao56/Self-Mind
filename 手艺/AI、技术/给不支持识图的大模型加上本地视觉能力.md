**关于给不支持识图的大模型加上本地视觉能力的分析**

**问题**

智能体时代，多模态是入场券，但很多前沿大模型推理能力强、代码写得好，却不支持图像输入。DeepSeek V4、GLM5.1 就是典型——代码、长上下文、agent 能力都特别棒，但一到真实任务里就受限。因为智能体面对的不是纯文本世界，截图、设计稿、PDF、图表报错、弹窗、漫画分镜，太多任务的关键信息藏在画面里。

实测：Cloud Code 接入 DeepSeek V4 Pro，喂一张图片，它没有直接说图里有什么，而是用 Python 读取图片文件信息（格式、尺寸、文件大小、EXIF）。让它用图像识别，它承认当前模型不具备视觉能力，返回 unsupported image。

**解决方案：手搓本地识图 skill**

让 DeepSeek 自己写一个 skill：先压缩图片，再扔给本地跑的千问 3.5 35B A3B 做图像识别，结果返回给 DeepSeek。全程用 Python 执行，又快又省 token。

**为什么不直接分享写好的 skill**

一键套用很香，但下载任何带可执行权限的都有安全隐患——你不知道哪个 skill 会不会把敏感信息（如 .env 文件里的 API Key）悄悄打包上传。建议尽量自建 skill。

**设置 Python 环境**

Cloud Code 会频繁安装和使用各种 Python package，新版 macOS 默认阻止全局安装。建一个干净独立的 VENV 环境事半功倍。目标：以后 Cloud Code 只要跑 Python，就默认使用自己专用的 VENV 环境。

**skill 代码要点**

- 本地 API 地址（llama.cpp 跑的千问 3.5 35B A3B）
- 识别图片的 prompt
- **图片压缩分辨率函数**（关键步骤）：原图太大直接转 base64 发给模型，推理速度巨慢。先把图片压缩，最长边限制在 1280
- 图片统一转 JPG quality 85，进一步压缩大小，然后转 base64
- 调用 API 识别图片的函数（llama.cpp 提供 OpenAI chat completion 兼容接口）
- timeout 最长等 120 秒（本地推理慢，可手工改成十分钟）

**生成后的调整**

- 默认模型名写死了 GPT-4O，本地没有——改成优先从接口获取当前可用模型
- 最大输出 token 默认 4096，复杂场景（如报纸 OCR）不够，本地模型 token 自由，改成 16K

**Cloud Code hook**

提供前置执行逻辑，在正式动用工具或执行指令前先自动跑一段 hook 脚本做验证。要求执行 Python 脚本必须走统一创建的虚拟环境，hook 机制动态拦截并重写 Python 命令的绝对路径。

**检查全局 claude MD**

AI 生成东西很快，但自己一定要清楚它动了哪里。它修改了全局 claude MD——每次 Cloud Code 启动都会读取的全局规则，很重要。检查发现加了两段 Python package 说明，很鸡肋（不是所有项目都需要 Python，容易跟实际环境不同步），直接删掉，保持全局规则纯净。加一条“除非特别约定，请永远使用中文回复”。测试：故意用英文问 list all my files，它用中文回复了，说明语言规则生效。

**原则**：针对特定任务加约束去项目级 claude MD；全局配置必须保持克制，只放真正通用的规则。

**本地部署设备要求**

- Windows/Linux：显卡显存最少 8GB，推荐 16GB
- Mac：内存最低 16GB，推荐 32GB 或更多
- 示例配置：16G 显存 V100 + 两根 16G DDR3 内存，跑 A3B 的 Q4KM 模型，速度接近 40 tokens/秒
- 跑不动 A3B：试 Gemma 4 E2B 或 E4B 小模型，识图能力不错，硬件要求低
- Mac mini M1 8GB 跑 E2B 约 27 tokens/秒

**为什么建议本地部署**：虽然麻烦，长期看划算，尤其有大量图片要处理时。本地模型不按量收费，隐私可控，数据不用传云端。

**偶尔用或不想折腾**：直接用千问或宇宙场的 coding plan，原生支持多模态。

**真实任务验证**

从两张杂志截图生成英语播客课件。截图是关于恐龙的 30 个小知识，图文混排复杂。拖入图片，Cloud 提示用生成的 skill 分析，两张同时识别。第一张 15 个点一个不少，第二张 15 个点也有了。然后转 TTS，用微软 edge TTS（免费效果可以）。在之前创建的 Python VENV 环境里安装 TTS package。生成语音和字幕，遇到语法错误、格式错误、网络并发问题都自己处理好了。

**踩坑**：网页 6.3 兆，因为把 base64 图片嵌入 HTML，污染上下文，导致第二阶段直接炸了，上下文速度极慢，费用也高。提示“不要把 base64 嵌入 HTML”后，文件大小 34KB。完整听了一遍播客，逐字对照原图，一个字没多一个字没漏。

**总结**

本地部署 A3B 补上云端模型（如 DeepSeek）的短板没那么难，亲测好用。混合推理场景未来会越来越普遍。
