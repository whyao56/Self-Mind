# 内容优化方法论 · 详尽版

> 照着做就行。每个动作都有标准、有模板、有验收、有真实跑过的输出。
> 概括版：[[内容优化方法论-概括版]]　完整推导：[[内容分型优化方法论-全流程报告]]
> 校验脚本：`模板/verify_append.py`（同目录）

---

## 一、适用条件

### 1.1 什么情况下用这套方法

同时满足这三条才用：

| 条件 | 说明 | 反例 |
|---|---|---|
| 是你**自己写的**内容 | 有自己的观察和判断在里头，才有"提炼"的空间 | 纯粹的剪藏、别人的原文转载 |
| 已有**正文** | 至少有一段成形的叙述或步骤 | 只有一个链接、只有一张图 |
| 将来会被**调用** | 会被查 / 做 / 想 / 练其中一种用到 | 存着只为"以后可能有用"（这类其实永远不会打开） |

### 1.2 判断流程

```
拿到一篇笔记
    │
    ├─ 是索引页 / 台账 / 库首页吗？ ──是──▶ 停。生成物，只维护不优化
    │                                         （改它们 = 下次重跑脚本就没了）
    └─ 否
        │
        ├─ 有正文吗？ ──没有──▶ 标「不足」，跳过。别硬优化空壳
        │
        └─ 有
            │
            └─ 正文是什么性质？
                ├ 我看过一件事之后的感想/复述  ──▶ 查型（仓库区/知识）
                ├ 要照着做的步骤/工具/命令     ──▶ 做型（仓库区/手艺）
                ├ 我这一天的记录               ──▶ 想型（日志/随笔）
                ├ 要背要记的材料               ──▶ 练型（书/语言/提示词）
                └ 我做过的项目复盘             ──▶ 报告型（全流程报告）
```

### 1.3 分型的适用条件

**① 查型（认知型）**

- 适用：看完视频 / 文章后用自己的话记下的内容笔记
- 特征：第一人称叙述、"刷到一个…"、"画面里…"、结尾一句自己的判断
- 适用前提：正文里**至少有一个可提炼的判断**。全是描述没有判断的，跳过
- 现状：`仓库区/知识/` 300 篇

**② 做型（执行型）**

- 适用：教程、工具清单、踩坑记录、配置步骤
- 特征：分点、含命令 / 路径 / 网址、有"第一步第二步"
- 适用前提：内容**指向一个可执行的动作**
- 现状：`仓库区/手艺/` 87 篇
- 特殊价值：**会过期**。半年后按钮改了、服务下架了，照着做就是返工

**③ 想型（内化型）**

- 适用：日志、随笔
- 特征：以日期为单位、多条并列、时间流水
- 适用前提：包含"我当时的想法"，不只是流水账
- 现状：`仓库区/日志` 12 + `旧日志` 4 + 随笔 2
- 注意：**这一类不用批量提示词**，逐日人工 + 模型协作，已有成熟做法

**④ 练型（重复型）**

- 适用：读书笔记、词表、提示词集
- 特征：条目化，将来要"复习"而不是"检索"
- 适用前提：条目可以被转成问题
- 现状：书 4 + 语言 1 + 提示词 8 + 模板 ≈ 20
- 注意：记忆靠**重复**不靠检索，所以要加的是复习机制，不是检索字段

**⑤ 报告型（产出型）**

- 适用：项目全流程报告
- 动作：抽「可复用方法」+「踩过的坑」
- 现状：`仓库区/全流程报告/` 37 篇

### 1.4 明确不适用

| 对象 | 为什么不动 |
|---|---|
| 31 个 `X 索引.md` | 脚本生成物，重跑就覆盖 |
| `工作区/军师/进度台账.md` | 唯一状态源，是活文件 |
| `库首页.md`、`图片索引.md` | 同上 |
| `仓库区/图片、附件/`（432 张） | 已在正文被引用，识图边际价值低 |
| 0 字节 / 只有链接的笔记 | 没有可提炼的内容 |

### 1.5 一句话边界

> 只要这篇笔记将来会被**查 / 做 / 想 / 练**其中一种方式调用，就适用；如果它永远只是"存着"，不适用。

## 二、原理

「光记不是目的」的落地方式只有一句：

> **优化的方向不按主题分（军事 / 健康 / 科技），按「这篇将来怎么被调用」分。**

为什么主题不是分型依据？因为主题决定**放在哪个文件夹**，不决定**怎么处理**。

同一篇讲「睡眠」的内容：

| 若它的用途 | 该处理成 | 因为 |
|---|---|---|
| 查（"人为什么需要深睡"） | 一句结论 + 场景 | 你要的是判断，不是过程 |
| 做（"怎么改善睡眠环境"） | 前置条件 + 失效风险 | 你要的是能照做、且知道什么时候不管用 |
| 想（"我那天为什么失眠"） | 保留原话与情绪 | 你要的是能回到当时的自己 |
| 练（"睡眠分几个阶段"） | 问题 + 答案 + 锚点 | 你要的是能背下来 |

主题一样，处理方式四样。所以**分类标签体系（领域/xxx）管"在哪"，调用方式管"怎么办"**——两者分工不同，都要有。

### 2.1 为什么是"追加"而不是"重写"

三个原因：

1. **可回滚** — 原文永远在。写错了删掉那个块就行
2. **可验收** — 追加块是新增内容，脚本能证明"原文一个字没丢"
3. **可分批** — 300 篇不用一次做完，做一半停下来库也是完好的

重写式优化没有这三点里的任何一点。

## 三、四型详解

### 3.1 查型

**识别特征**

```
[视频标题_哔哩哔哩_bilibili](https://...?spm_id_from=...)
刷到一个FPV无人机视角的视频。
画面里，两个俄罗斯士兵偶遇一架躲在草丛里的FPV无人机……
Tags: #FPV无人机 #战争 #绝望 #人性 #瞬间
```

**问题**：半年后只记得"我看过个无人机视频"，想不起当时得出什么判断。要重新读 300 字。300 篇堆起来就是 60 万字。

**追加块模板**

```
@@@ <文件名>
结论：<一句话陈述句>
场景：<当我在做 X 的时候> / <场景2>
补漏：<补法 或 无>
@@@
```

**每一项的标准**

| 项 | 合格 | 不合格 |
|---|---|---|
| 结论 | "真正的绝望不是喊叫，是身体先反应、表情还没来得及跟上。" | "讲了一个关于战争的视频。"（空壳）<br>"我们要珍惜和平。"（拔高成鸡汤） |
| 场景 | "写人物濒死的段落" | "增长见识"（空话） |
| 补漏 | "FPV 是穿越机第一人称视角，画面抖动大" | 补成一段背景介绍（太长，喧宾夺主） |

**验收**
- [ ] 结论是陈述句，脱离原视频能读懂
- [ ] 场景具体到动作
- [ ] 原 BV 号 / 图片引用 / Tags 行 0 丢失

---

### 3.2 做型

**识别特征**：分点的工具 / 步骤 / 命令，带网址或代码。

**问题**：这类内容**会过期**。半年后按钮位置改了、命令参数变了——你还照着做，白折腾。而笔记里**没有任何"我验证过没有 / 什么时候可能失效"的信息**。

**追加块模板**

```
@@@ <文件名>
解决什么：<一句话>
前置条件：<软件版本/账号/权限/系统环境；原文没写就写「原文未写」>
失效风险：<最可能随时间失效的点，至少 1 条>
验证状态：<已验证 <日期> / 未验证>
@@@
```

**每一项的标准**

| 项 | 合格 | 注意 |
|---|---|---|
| 解决什么 | "用脚本给常用网站打补丁，去掉广告弹窗、自动翻页" | 不要复述目录 |
| 前置条件 | "浏览器已装脚本管理器；访问源站需 VPN" | **原文没写就写「原文未写」**，不要替原文猜一个填上 |
| 失效风险 | "源站国内需 VPN，若被墙则脚本全部无法获取" | 至少 1 条；指向**具体的**机制 |
| 验证状态 | "未验证（原文只有清单，无使用痕迹）" | 不要美化 |

**验收**
- [ ] 有明确的「前置条件」行
- [ ] 至少 1 个「最可能失效的地方」
- [ ] 命令 / 代码块 / 网址 **0 丢失**

---

### 3.3 想型

不做批量提示词。逐日推进，固定格式见 [[2026-08-04]]（成稿样板）。

**标准**：补背景、消除指代依赖、跨条目关联、保留原观点与情绪；**不加元叙述、不加解释性小标题、不加层级前缀**。

**范围硬规则**：严格等于该 `.md` 文件里**现有的条目数**，不去 git 历史或别的目录补"这一天原本还有几条"。

---

### 3.4 练型

**追加块模板**

```
@@@ <文件名>
问题：<能用来考自己的问题>
答案要点：<3 句以内>
锚点：<一个画面/比喻/例句>
@@@
```

**词表专用变体**

```
@@@ <词>
词义：<不超过 15 字>
例句：<造一个简单例句>
易混：<和哪个词最容易混；没有写「无」>
@@@
```

**验收**
- [ ] 每个条目都能问出一个问题
- [ ] 词条有例句或锚点

**额外动作**（这一类特有）：frontmatter 加复习字段，让"该复习了"可被检索：

```yaml
复习: 未开始        # 未开始 / 进行中 / 已掌握
下次复习: 2026-10-23
```

---

### 3.5 报告型

```
@@@ <文件名>
可复用方法：
1. ...
2. ...
踩过的坑：<真正走了弯路的点>
可省掉：<事后看多余的步骤>
可提前：<应该更早开始的步骤>
@@@
```

要求：**脱离本项目也成立**——把项目专有名词替换成通用的。

## 四、流水线七步

```
① 分批 ──▶ ② 选提示词 ──▶ ③ 出追加块 ──▶ ④ 校验
                                              │
                            ⑦ 提交 ◀── ⑥ 抽检 ◀── ⑤ 追加
```

### ① 分批

- **每批 10 篇**（约 2.5 万字），稳定不丢条
- **按领域切**，不跨领域混批 —— 同领域上下文一致，模型总结质量更高
- 先跑**一个领域 9–12 篇**做样板，格式确认后再全量

### ② 选提示词

一次只跑**一种类型**。混合类型会让输出格式漂移。提示词见 [[笔记内容优化-提示词包]]。

### ③ 出追加块

模型只输出结构化块，**不重写原文**。输出格式用 `@@@ <文件名>` 分隔，便于程序解析。

### ④ 校验（**这一步不能跳**）

```bash
python 模板/verify_append.py <原文件> <写入后的文件>
```

三项比对 + 两项自查：

| 检查项 | 要求 |
|---|---|
| 内联 Tags 行标签种类 | 0 丢失 |
| BV 号 | 0 丢失 |
| 图片引用（文件名） | 0 丢失 |
| 元叙述（"这条笔记是为了…""失忆"等） | 0 处 |
| 层级前缀（`#内核/xxx`） | 0 处 |

> ⚠️ **一个真实的坑**：全库有 **39 篇笔记的 `Tags:` 行折成了两行**（例如 `油猴插件.md`：
> `Tags: … #网页加速` 换行 `#看图工具 #比价`）。校验脚本必须把续行一起吃进去，
> 否则这 39 篇的标签会**漏检**——丢了也报"OK"。`verify_append.py` 已处理。

### ⑤ 追加

写入笔记末尾。同时在 frontmatter 加幂等标记：

```yaml
整理: 2026-10-16
```

好处：重复跑不会重复追加；也能用搜索 `["整理": 2026-10-16]` 查出进度。

### ⑥ 抽检

每批**人工看 2 篇**。看三件事：结论有没有拔高、场景是不是空话、有没有编造原文没有的信息。

**跑偏就停**，改提示词重跑这一批，不要带着错误样本往下推。

### ⑦ 提交

每批一次 commit：

```bash
cd /d/Obsidian/Documents/MyDigitalBrain
git add -A
git commit -m "优化(做型)：浏览器与网络 9 篇追加块"
```

坏了一个 `git reset --hard <上一批>` 就回来。

| 项 | 值 | 理由 |
|---|---|---|
| 每批条数 | 10 | 约 2.5 万字，稳定不丢条 |

## 六、排错手册

| 症状 | 原因 | 处理 |
|---|---|---|
| 漏条（10 条只出 8 条） | 批太大 / 模型截断 | 降到 5 篇一批；检查输入是否用了 `===` 分隔 |
| 结论写成"讲了一个关于 X 的视频" | 提示词约束不够 | 在该型提示词里加一句"结论必须是判断句，不是内容介绍" |
| 出现"这条笔记是为了…" | 通用约束没带上 | 通用约束必须**每条提示词前面都加** |
| 标签被擅自改了 | 模型越界 | 通用约束第 1 条已禁止；校验脚本会抓出来 |
| 校验报"标签丢失"但看着没丢 | Tags 行折行被截断 | 用本目录 `verify_append.py`（已处理续行），别自己写正则 |
| 追加块位置不对（跑到 frontmatter 里） | 写入位置判断错 | 必须写在**正文末尾**，即最后一行 `Tags:` 之后 |
| 追加了两遍 | 没记幂等标记 | 先查 `["整理":` 再跑 |
| 某一型怎么跑都不对 | 型选错了 | 回到 1.2 的判断流程复核 |

## 七、完整演示实例 · 做型

一遍走完七步。用的是一篇**真实笔记**，校验输出是**真跑出来的**。

### 第 0 步 · 选型

文件：`仓库区/手艺/浏览器与网络/油猴插件.md`

判断依据：
- 位置在 `仓库区/手艺/` → 指向「做」型
- frontmatter `类型/教程` → 与「做」型一致
- 正文形态：标题是「10 款油猴脚本的推荐整理」，内含 4 个网址代码块 + 逐条工具说明，是**要照着装的东西**

三个信号一致 → 定为**做型**。

### 第 1 步 · 分批

同一目录共 9 篇，先全量试跑：

```
仓库区/手艺/浏览器与网络/
  Edge 浏览器阻止不安全下载.md
  Edge浏览器插件.md
  Edge浏览器设置.md
  Via浏览器.md
  下载谷歌翻译音频.md
  互联网核心协议.md
  油猴插件.md
  解决edge浏览器显示"你尚未连接"的问题.md
  访问Github和HuggingFace工具.md
```

> **边界提醒**：`互联网核心协议.md` 其实是**协议原理知识**，不是教程。
> 分型不能只看目录，要看正文性质——这一篇应该归到查型。
> 这就是第 6 步抽检要抓的东西。

### 第 2 步 · 选提示词

通用约束 + 做型提示词（全文见 [[笔记内容优化-提示词包]]）。

### 第 3 步 · 拼装输入

```
【通用约束 · 必须遵守】
1. 绝对不改动我的原文。你只输出"追加块"，我会把它贴到笔记末尾。
2. 不要写元叙述：不出现"这条笔记""本记录""为将来""以备查阅"这类话。
3. 不要写解释性小标题。
4. 标签直接写短语本身，不要任何层级前缀（不写 内核/xxx、本质/xxx）。
5. 不要复述原文，不要加评价性的话。
6. 输出格式必须严格遵守我给的模板，用 @@@ 分隔每一条。
7. 如果某条信息不足以完成要求，就写「不足」，不要编造。

你是我的操作手册审核助手。读下面这批笔记（每批 10 条）。
它们是教程、工具清单、踩坑记录这类"要照着做"的内容。

对每一条，输出四项：
1. 解决什么 —— 一句话说清这条能解决什么问题。
2. 前置条件 —— 照着做之前需要具备什么（软件版本、账号、权限、系统环境、依赖项）。
   原文没写就写「原文未写」，不要替我猜一个填上。
3. 失效风险 —— 这条里最容易随时间失效的部分是什么。至少写 1 条。
4. 验证状态 —— 判断这条是否留下了"我试过"的痕迹。没有就写「未验证」。

输出格式：
@@@ <文件名>
解决什么：<一句话>
前置条件：<...>
失效风险：<...>
验证状态：<已验证 <日期> / 未验证>
@@@

注意：命令、代码、路径要原样引用，不要改写或补全。

=== 文件：仓库区/手艺/浏览器与网络/油猴插件.md
标题：油猴到底有多香？10个小众但效果拔群的优化"补丁"
正文：
**关于 10 款油猴脚本的推荐整理**
来源：Greasy Fork（国内最方便的脚本网站，需 VPN）。……
（此处为原文全文，含 4 个网址代码块）
Tags: #油猴脚本 #GreasyFork #浏览器插件 #网盘助手 #搜索引擎 #网页加速
#看图工具 #比价
===
```
