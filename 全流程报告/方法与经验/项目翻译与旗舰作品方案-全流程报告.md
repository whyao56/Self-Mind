# 项目翻译与旗舰作品改造方案

> 版本 v1.0 ｜ 2026-10-10 ｜ 军师执行层文件
> 解决的问题：**你的项目很好，但 HR 看不懂它和"信管应届生投 AI 岗"的连接点。**

---

## 〇、核心问题

你现有项目的共同缺陷（对就业而言，不是对技术而言）：

| 缺陷 | 表现 | 后果 |
|---|---|---|
| **自用工具定位** | "帮我记聊天记录""帮我做知识库" | 面试官看不出商业场景 |
| **缺量化成果** | 有测试数、代码行数，但无"影响"指标 | 简历上没有数字 = 没有项目 |
| **技术堆栈陈述式** | 写"用了 FastAPI + SQLite + pywebview" | 像技术清单，不像解决问题 |
| **缺"为什么不用另一个"** | 部分报告有，但未提炼到简历 | 面试官最爱问这个 |

**翻译的本质**：把"我做了什么"改成"我解决了什么有难度的问题，用什么方法，效果如何"。

## 一、项目翻译公式

### 简历条目结构（STARR + 量化）

```
[项目名] | [角色] | [时间]
· 背景（S）：为____场景，解决____问题
· 任务（T）：我负责____
· 动作（A）：用____技术，做____关键决策（此处埋面试钩子）
· 结果（R）：量化指标（____从 A 提升到 B）
· 复盘（R）：我知道了____（可选，体现成长性）
```

### 量化指标从哪来

你的项目里**已经有**，只是没提炼。示例映射：

| 原始素材 | 可提炼的指标 |
|---|---|
| RAG：55 测试、40 条评测集、8 篇语料 76 切块 | **构建 40 条人工标注评测集，召回率____** |
| RAG：BM25 + 向量双路 | **混合检索相比单一向量检索，召回提升____%** |
| tidewatch：161 测试、3200 行、十条信号三层 | **可解释性：每条结论可追溯至规则+证据+贡献分** |
| tidewatch：不用 GPU/API Key，仅依赖 PyYAML | **零外部依赖，单机可跑，部署成本 0** |
| WingMan：241 测试、7 Release、35450847 字节包 | **7 次版本迭代，241 项测试全绿，发行包确定性构建可校验** |
| WingMan：重写 commit 历史清邮箱 | **主动做隐私合规：扫描并彻底清除全历史提交元数据** |

> ⚠️ **行动项**：上面几个"____"必须你去实测填上。**没有实测数字的量化是撒谎，面试会拆穿。**

## 三、旗舰作品改造清单（RAG 为例）

### 3.1 必须补的量化数据

- [ ] **检索质量对比**：单路 vs 混合检索的 Recall@K / MRR，做出表格
- [ ] **延迟数据**：P50 / P95 检索与生成延迟
- [ ] **切块策略对比**：3 种策略的检索效果差异
- [ ] **拒答准确率**：能不能正确拒答超纲问题

### 3.2 README 改造（给面试官看的第一眼）

当前 README 偏"技术文档"，需补：
- [ ] **顶部一句话**：一句话说清"这是什么、解决什么问题"
- [ ] **架构图**：已有，保留
- [ ] **量化成果表**：放最显眼位置
- [ ] **快速开始**：3 行命令能跑起来（降低面试官试用成本）
- [ ] **设计取舍**：单独一节，列"为什么这样选"
- [ ] **截图/演示**：有界面就要放图

### 3.3 埋面试钩子（关键技巧）

主动在简历/README 里埋 3-5 个"能被追问"的点，且**你已准备好答案**：

| 钩子 | 面试官可能追问 | 你要准备好的答案 |
|---|---|---|
| 混合检索 | 为什么用 BM25 + 向量而不是只用一个？ | 关键词精确匹配 vs 语义匹配的互补性 + 实测数据 |
| 三策略切块 | 什么场景用哪种？ | 文档结构决定的取舍逻辑 |
| 拒答机制 | 怎么判断该拒答？ | 阈值设计 + 误拒/漏拒的权衡 |
| 评测集 | 40 条怎么标？够吗？ | 标注标准 + 承认样本量的局限 |
| 避开 Agent 框架 | 为什么？ | 你的原话："那个阶段写出来也讲不清" |

## 四、简历项目条模板（直接可用）

### RAG 知识库问答系统（AI 应用工程 · 个人项目 · 2026.10）

- **背景**：构建垂直领域 RAG 问答系统，解决通用 LLM 在专业文档上的幻觉与不可控问题
- **方案**：设计「离线建库 + 在线问答」双链路；实现三种切块策略并实测对比；采用 BM25 + 向量混合检索；构建拒答机制降低幻觉
- **工程**：26 个源文件 / 约 4300 行；55 项测试全通过；CI 双 job；Docker Compose 一键启动；零 API Key 可跑离线基线
- **结果**：构建 40 条人工标注评测集，混合检索相比____召回提升____%，P95 延迟____ms
- **亮点**：刻意规避现成 Agent 框架，从链路底层实现，保证每个模块可解释、可替换

### tidewatch 网络水军识别引擎（可解释算法 · 个人项目 · 2026.10）

- **背景**：识别网络水军与协同行为，核心难点是"不能只看单账号，要看协同性"
- **方案**：设计三层架构 + 十条信号；每条结论可追溯至「哪条规则、哪个证据、贡献多少分」
- **工程**：3200 行（源码 1900 + 测试 1300）；161 项测试全绿；仅依赖 PyYAML
- **结果**：零 GPU、零 API Key、零数据库，单机可运行

### WingMan 聊天僚机（AI Agent 应用 · 个人项目 · 2026.08-10）

- **背景**：把聊天记录交给大模型记忆，实时给出回复建议
- **方案**：FastAPI + 单文件 HTML 前端（零构建）+ pywebview 桌面壳；本地 SQLite 隐私优先
- **工程**：7 次版本迭代（v0.2.0）；**241 项测试通过**；PyInstaller 打包，构建确定性可校验
- **合规**：主动扫描并重写 git 全历史，清除提交元数据中的邮箱泄露
