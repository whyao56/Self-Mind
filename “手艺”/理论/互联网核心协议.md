**关于互联网核心协议的分析**

**IP（Internet Protocol）**

IP 是整个互联网的绝对基础。每台联网设备都有 IP 地址，像家庭住址一样标识网络中的设备。1981年9月 RFC-791 为 DARPA 正式制定。设计者不是在造商业产品，而是在造能承受核攻击的军事通信系统——没有单点故障、没有中央控制，这就是今天互联网去中心化的原因。

IP 把数据切成小包（packets），像把一本书每页撕下来装进单独信封寄到同一个地址。
![[图片、附件/Pasted image 20260926220408.png]]

每个包包含头部：源 IP、目标 IP、TTL（限制经过多少路由器后被丢弃）、校验和（检测损坏）。

IPv4 地址 32 位，最多 43 亿个。
![[图片、附件/Pasted image 20260926220455.png]]

1981年看似无限，2011年 IANA 分发完最后一个 IPv4 块。IPv6 用 128 位地址，340 万亿亿亿亿个（340 后面 36 个零）——给地球上每个原子分配一个还有剩余。
![[图片、附件/Pasted image 20260926220628.png]]

IP 最关键的特性：**完全无连接、不可靠**。RFC-791 明确说 IP 只负责从源到目标传递数据包，不保证到达、不保证按序到达、不保证到达。**IP 只管路由和转发**，然后就不管了。互联网所有可靠的东西都是其他协议在 IP 之上构建的。

**TCP（Transmission Control Protocol）**

TCP 的全部目的就是修复 IP 不保证的一切（丢包、乱序、重复发送）。对实时流媒体，丢包可以接受；但对固件更新（少一个字节设备变砖）、金融交易（少一个字节损失百万），不可接受。

TCP 在 IP 上加了三个东西：**连接**（数据移动前双方握手确认准备好通信）、**序列号**（每个字节有序列号，接收方知道什么到了什么没到）、**确认与重传**（接收方确认每个收到的段，发送方在重传超时内没收到确认就自动重发）。
![[图片、附件/Pasted image 20260926220942.png]]

此外还有**滑动窗口**做流量控制（防止快发送方淹没慢接收方）和**拥塞控制**算法（检测到丢包时退让）。
![[图片、附件/Pasted image 20260926221041.png]]

结果是两端之间保证有序可靠的字节流——这就是 HTTP、HTTPS、MQTT、WebSocket 都跑在 TCP 上的原因。

**UDP（User Datagram Protocol）**

UDP 是 TCP 的刻意反面。TCP 保证交付、顺序、完整性；UDP 全部扔掉。RFC 768，1980年8月由 John Postel 制定——就是写 TCP 的同一位工程师。它跑在 IP 上，但移除了所有可靠性机制：无握手、无序列号、无确认、无重传、无流量控制、无拥塞控制。

UDP 把数据包进最小 8 字节头部（源端口、目标端口、长度、校验和），发送后不确认到达。TCP 头部最小 20 字节，UDP 只有 8 字节——服务器处理百万并发连接时这个差别巨大。

UDP 存在的真正原因是**延迟**。TCP 的握手、确认、重传都引入延迟，某些应用完全不能接受。视频通话丢一帧，你不希望 TCP 停下来检测缺失确认、等重传超时、重传、半秒后才送到屏幕——那时对话已经继续了，显示旧帧更糟。你想要下一帧，哪怕稍微降质。人眼对丢帧的容忍远好于半秒卡顿。

UDP 的设计哲学：**接受不完美换速度**。视频流（丢包是瞬间故障而非暂停）、在线游戏（一毫秒额外延迟决定胜负）、语音通话（瞬间杂音好过半秒冻结）、DNS 查询（简单查询响应需在10毫秒内完成，UDP 只需两个包，TCP 至少七个包）。

**DNS（Domain Name System）**

DNS 是互联网的电话簿。你输入域名，设备向 DNS 解析器发查询，解析器检查缓存，有答案立即返回；没有就查根服务器、顶级域服务器、权威名称服务器，直到找到正确 IP。整个过程不到50毫秒。每次访问新网站，DNS 默认用 UDP 53端口，因为查询小而快。

一个重要细节：DNS 默认完全未加密，你的网络提供商能看到你查询的每一个域名。DNS over HTTPS 通过在正常网页流量中加密 DNS 查询来解决这个问题。

**HTTP（Hypertext Transfer Protocol）**

浏览器和 Web 服务器对话的语言。1989年 Tim Berners-Lee 在 CERN 发明。简单的请求-响应模型：浏览器发送请求带方法（GET 获取资源、POST 处理数据、PUT 更新资源、DELETE 删除），服务器返回三位状态码（200 成功、404 未找到、500 服务器出错）。

HTTP/2（2015）允许一个连接上多个请求同时进行。HTTP/3（2022）用 QUIC 替代 TCP 降低延迟，尤其在移动网络。

**HTTPS（HTTP Secure）**

HTTP 跑在 TLS 创建的加密隧道里。没有 HTTPS，你发送的每个字节都是明文——每个密码、信用卡号，任何拦截流量的人都能看到。HTTPS 用 TLS 握手做三件事：用数字证书认证服务器；在浏览器和服务器之间建立共享加密密钥（密钥从不在网络上传输）；用 AES-256 加密所有流量，中间任何人看到的字节都完全不可读。现在超过 85% 的 Web 流量加密，是处理用户数据的网站的最低标准。

**MQTT（Message Queuing Telemetry Transport）**

为 HTTP 从未设计的世界而生。1999年 IBM 的 Andy Stanford-Clark 和 Arcom 的 Arlen Nipper 创建，用于通过卫星监控偏远沙漠的石油管道——连接昂贵、不可靠、设备几乎没有处理能力。

MQTT 用发布-订阅模型：设备向中央服务器（broker）发布消息，其他设备订阅 broker 只接收关心的消息。没有设备直接对话。MQTT 最小包只有 2 字节，HTTP 是几百字节——这种极小开销使 MQTT 成为 IoT 设备标准。智能恒温器、联网传感器、工业监控器几乎肯定在用 MQTT。

**WebSocket**

让实时 Web 应用成为可能的协议。HTTP 从未为需要即时推送数据的应用设计——实时股价、聊天消息、多人游戏。旧的变通是轮询：浏览器每秒问服务器有没有变化，浪费、慢、没必要。

WebSocket 2011年12月 RFC 6455 标准化。以正常 HTTP 请求开始，但要求服务器升级连接。服务器返回 101 状态码（切换协议）。连接现在变成持久的全双工通道，双方随时发数据不用等。服务器在变化发生的瞬间推送数据，无轮询、无延迟、无浪费请求。每个实时聊天应用、交易平台、多人浏览器游戏、实时协作工具（如 Google Docs）都在用 WebSocket。
