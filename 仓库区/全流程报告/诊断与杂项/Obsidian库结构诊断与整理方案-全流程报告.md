# Obsidian 库结构诊断与整理方案

扫描对象是 `D:\Obsidian\Documents\MyDigitalBrain\`，全库只读遍历了 593 个文件、9 个顶层目录。

本文是建议书。没有移动、重命名或删除任何文件。

## 一、结论

库的问题不在于分类太多，而在于三个地方没有分层：附件全平铺（228MB、433 个文件挤在一层）、`手艺/AI、技术` 55 个文件挤在一层、`全流程报告` 把三种不同性质的东西混在一层。另外有 3 处重复或错放、1 个带全角引号的目录名、1 个失效配置。

建议的动作总量是：改 4 个、增 3 个、清理 3 处。不动内容，只动位置。

## 三、发现的 7 个问题

### 问题 1：附件目录单层平铺 433 个文件（最严重）

`图片、附件/` 里 432 张图加 1 个误入的 md，全部堆在一层。命名分三类：

| 命名模式 | 数量级 | 问题 |
|---|---|---|
| `Pasted image 2026MMDDHHMMSS.png` | 约 380 | 粘贴自动生成，名字无任何语义，只能靠日期猜 |
| `ChatGPT Image 2026年8月X日 ...png` | 3 | 同上 |
| 一串哈希（`cb9e80d3...raw.jpg`） | 约 40 | 同上 |

后果是文件浏览器要滚动 400 多行才能定位一张图，无法从文件名判断用途，也无法判断哪张图属于哪篇笔记。

更关键的一点：这些图片被笔记以绝对路径嵌入引用（形如 `图片、附件/Pasted image 20260803215504.png`），全库有 400 处这样的引用。所以绝不能用 Windows 资源管理器拖动这些图，一拖就断 400 个链接。

### 问题 2：`“手艺”` 目录名带全角引号

目录实际名字是 `“手艺”`，含中文全角引号 U+201C 和 U+201D，不是 `手艺`。

麻烦在这些地方：命令行、脚本、Git 操作都要额外转义，容易和半角引号混淆；跨工具同步（GitHub、网盘、手机端）时，非 ASCII 标点在个别环境下会变乱码；在笔记里写 `[[手艺/xxx]]` 也链接不上，因为真名带引号。

### 问题 3：`手艺/AI、技术` 55 个文件塞一层，混装 5 类内容

这 55 个文件至少横跨 5 个完全不同的领域：

| 实际内容 | 例子 | 数量 |
|---|---|---|
| AI 工具与模型 | DeepSeek V4 三条、Cherry Studio、LM Studio、Claude Code | 12 |
| 开发与工具 | Git/GitHub 六条、VS Code、Pycharm 破解、Typora 破解 | 12 |
| Windows 系统操作 | 清理 C 盘、定时关机、双显示器、触摸板、重装 Win7 | 17 |
| 浏览器与网络 | Edge 四条、Via、油猴、访问 GitHub 工具 | 8 |
| 学习提示词 | Python / SQL / 数据库 / 计算机网络入门提示词 | 6 |

「清理 C 盘」和「DeepSeek V4 替代 Claude Code」躺在一起，找起来只能靠搜索。

### 问题 4：`手艺/理论` 算法、数学、网络混装

13 个文件里，算法可视化 8 个（各种排序、二分查找、0-1 背包）、数学 3 个（傅里叶、欧拉公式、泰勒展开）、计算机网络 1 个（互联网核心协议）、概念 1 个（时间复杂度）。

### 问题 5：3 处重复与错放

蓝牙耳机报告完全重复。`全流程报告/蓝牙耳机音频降速-全流程报告.md` 和 `图片、附件/蓝牙耳机音频降速-全流程报告.md` 的 MD5 完全相同（`f7daad4b...`）。

「用 AI 做项目」同源两版。`全流程报告/用 AI 做项目-项目经验.md`（48KB，有 frontmatter）和 `“手艺”/AI、技术/用 AI 做项目-经验清单.md`（无 frontmatter），同源于 WingMan 项目，内容重叠。

`全流程报告/` 里混进了非报告文件。`牧野森外套-黑色款选款信息汇总.{md,html,csv}` 三件套加 `淘宝桌面端-CLI通道诊断与替代方案.md`，是选款清单和排障记录，不属于全流程报告体系。

### 问题 6：3 个结构冗余或失效点

`快记、随笔/` 里只有 1 个 `未命名.md`（99 字节），是空壳目录，占了位置但没在用。

`参考模板/`：`.obsidian/templates.json` 里配了 `"folder": "参考模板"`，但该目录不存在，模板功能配了没用。

### 问题 7：元数据与双链几乎为零

159 篇笔记里只有 7 篇有 `tags`，占 4.4%。全库只有 1 条笔记间双链。

这意味着现在完全依赖文件夹做分类。文件夹只能表达一个维度，比如「AI与模型」，可笔记天然有多个维度（领域、类型、状态、项目）。文件夹一旦定了，跨维度检索就只能靠全文搜索。

这是"感觉乱"的根本原因。不是目录多，是没有第二条组织轴。

## 七、附件专项

`图片、附件/` 是 228MB、433 个文件，但不建议现在大批量整理。原因说在下面。

### 为什么风险高

全库有 400 处图片引用，用的是绝对路径格式（形如 `图片、附件/xxx.png`）。

`.obsidian/app.json` 里 `alwaysUpdateLinks: true`，只在 Obsidian 应用内移动时才会自动重写链接。

用 Windows 资源管理器拖，等于 400 个链接同时失效，而且 Obsidian 无法自动修复，因为是绝对路径，不会按文件名找回。

### 建议的分级策略

A 级，推荐先做：新建 `图片、附件/_归档/` 和 `图片、附件/_未引用/`，把确认未被引用的约 32 张孤儿图放进 `_未引用/`。零风险，收益中等。

B 级，推荐：改 `app.json` 的 `attachmentFolderPath` 为 `图片、附件/未整理`，从今天起新粘贴的图都进新目录，老的不动。零风险，收益中高，能阻止问题继续恶化。

C 级，谨慎：把已有 400 张图按 `图片、附件/日志图/2026-08/` 这样的批次分流。中高风险，务必在 Obsidian 内操作，每批不超过 50 张，做完立刻抽查。收益高。

D 级，不推荐：一次性全量重命名 400 张图使其有语义。风险极高，收益低。

无论做哪一级，先做 Git 提交。有 obsidian-git 插件，提交一次等于拿到完整回滚点，之后怎么折腾都能 `git checkout` 还原。这是把高风险操作降到可承受的最简办法。

```

        · “手艺” → 手艺
        · 手艺/其他 → 手艺/软件与娱乐
        ↓
第 3 步｜拆解扁平层（本次收益最大）
```

## 九、比文件夹更重要的事：补上第二条组织轴

目录只有 9 个、笔记只有 159 篇，数量上完全不算多。但只有 4.4% 的笔记有标签，全库只有 1 条双链。也就是说，所有笔记都是孤岛，只能按文件夹路径找到它们。

目录结构不合意时，传统做法是重排目录，可目录只能表达一个维度。笔记其实有多个维度：

```
领域轴：AI / Windows / 网络 / Office / 理论   ← 现在只有这一轴
类型轴：教程 / 提示词 / 踩坑记录 / 项目报告 / 读书笔记
状态轴：草稿 / 已整理 / 已归档
项目轴：WingMan / tidewatch / Etude / 军师
```

建议做 3 件事，都很轻。

一是给每篇加 tags。比如 `清理 C 盘.md` 加 `tags: [Windows, 系统维护, 踩坑]`。加完就能用标签面板一次筛出所有 Windows 相关的踩坑记录，不用管它在哪个文件夹。模板已经配好，修好 `参考模板/` 之后，新建笔记时填 `tags:` 就行。

二是建 2 到 3 个 MOC（内容地图）。比如在 `手艺/` 下建 `手艺总览.md`，用双链把各子目录的代表笔记串起来。这是把 87 篇散笔记变成一张网的开始。

三是把「快记、随笔」当收集箱用。随手记先扔这里，每周整理一次分流到对应目录，而不是让所有笔记一步到位塞进 87 个里的某一个。

## 十、不建议做的事

不引入 PARA、Johnny.Decimal 这类企业级编号体系。库只有 159 篇笔记、单人使用，`00-` `01-` 这类前缀是给几十人协作、上千文件准备的，对你是纯粹的负担。

不一次性全量重命名 400 张图片，风险极高、收益极低，见第七节 D 级。

不把「日志」47 篇按天拆散或合并。日志格式统一（`YYYY-MM-DD.md`），daily-notes 配置正确，这是库里最健康的部分，别动。

不拆掉「军师」目录。它是活跃状态文件（进度台账加每日流水），机制正在运行中，和归档类目录性质不同，应保持独立。

不为整齐合并 `书`、`语言` 这类小目录。4 篇、1 篇的目录不叫乱，叫规划中的空位，它们各自代表独立的长期主题。
