# 内容优化提示词包

配套《内容分型优化方法论》。

用法：按笔记类型选一条提示词，连同「通用约束」一起发给模型，把笔记按「输入格式」贴进去，拿到「追加块」，再用脚本写入。

## 〇、通用约束（每条提示词前面都要加这一段）

```
【通用约束 · 必须遵守】
1. 绝对不改动我的原文。你只输出"追加块"，我会把它贴到笔记末尾。
2. 不要写元叙述：不出现"这条笔记""本记录""为将来""以备查阅"这类话。
3. 不要写解释性小标题：不要"这是什么""我的判断""背景知识"这类。
4. 标签直接写短语本身，不要任何层级前缀（不写 内核/xxx、本质/xxx）。
5. 不要复述原文，不要加评价性的话（"很不错""值得学习"之类）。
6. 输出格式必须严格遵守我给的模板，用 @@@ 分隔每一条，方便我程序化解析。
7. 如果某条信息不足以完成要求，就写「不足」，不要编造。
```

输入格式（把这一批笔记按这个拼好再发）：

```
=== 文件：<相对路径，如 仓库区/手艺/浏览器与网络/Edge浏览器插件.md>
标题：<笔记标题>
正文：
<笔记正文全文，含 Tags 行>
===
```

## 一、查 · 认知型（`仓库区/知识/` 300 篇）

```
你是我的知识库整理助手。读下面这批笔记（每批 10 条，以 === 分隔）。
它们是我看完视频后用自己的话记下的内容笔记。

对每一条，输出三项，不要复述原文：

1. 结论 —— 用一句陈述句写出这条的可复用判断。要求：脱离原视频也能读懂；
   写成"某个道理/规律是什么"，不要写成"讲了关于 XX 的视频"。
2. 场景 —— 列 1–3 个具体的使用时机，格式"当我在做 X 的时候"。
   要具体到动作，不要写"增长见识""开阔视野"这类空话。
3. 补漏 —— 如果原文里有"需要背景知识才能读懂"的地方、或明显的笔误/指代不清，
   用一行写出该怎么补。没有就写「无」。

输出格式（严格照这个来）：

@@@ <文件名>
结论：<一句话>
场景：<场景1> / <场景2>
补漏：<补法 或 无>
@@@

注意：结论要克制，不要拔高成鸡汤；也不要把我的观点改写成更强的断言。
```

## 二、做 · 执行型（`仓库区/手艺/` 87 篇）

```
你是我的操作手册审核助手。读下面这批笔记（每批 10 条）。
它们是教程、工具清单、踩坑记录这类"要照着做"的内容。

对每一条，输出四项：

1. 解决什么 —— 一句话说清这条能解决什么问题。
2. 前置条件 —— 照着做之前需要具备什么（软件版本、账号、权限、系统环境、
   依赖项）。原文没写就写「原文未写」，不要替我猜一个填上。
3. 失效风险 —— 这条里最容易随时间失效的部分是什么（按钮位置改版、
   命令行参数变更、服务下架、需要付费等）。至少写 1 条。
4. 验证状态 —— 判断这条是否留下了"我试过"的痕迹。没有就写「未验证」。

输出格式：

@@@ <文件名>
解决什么：<一句话>
前置条件：<...>
失效风险：<...>
验证状态：<已验证 <日期> / 未验证>
@@@

注意：命令、代码、路径要原样引用，不要改写或补全。
```

## 三、产出型（`仓库区/全流程报告/` 37 篇）

```
你是我的项目复盘助手。读下面这篇报告。
输出四项：

1. 可复用方法 —— 把这个项目里用到的做法抽成 3–5 步，要求脱离本项目也成立
   （把项目专有名词替换成通用的）。
2. 踩过的坑 —— 列出真正走了弯路的点，不要罗列所有细节。
3. 下次可以省掉的动作 —— 哪些步骤事后看是多余的。
4. 下次可以提前做的动作 —— 哪些应该更早开始。

输出格式：

@@@ <文件名>
可复用方法：
1. ...
2. ...
踩过的坑：<...>
可省掉：<...>
可提前：<...>
@@@
```

## 四、练 · 重复型（书 / 词表 / 提示词 20 篇）

```
你是我的复习设计助手。读下面这批学习材料。

对每一条，输出三项：
1. 问题 —— 把这条转成一个能用来考自己的问题（将来我只看问题，答不出来就回来看原文）。
2. 答案要点 —— 3 句以内，脱离原文能读懂。
3. 记忆锚点 —— 给一个画面、比喻或例句，帮我把这条记住。

输出格式：

@@@ <文件名>
问题：<...>
答案要点：<...>
锚点：<...>
@@@
```

词表专用变体（`语言/道本语/词汇.md` 这类，先做 OCR 再跑）：

```
读下面这批词条。对每个词条输出：
@@@ <词>
词义：<不超过 15 字>
例句：<造一个简单例句>
易混：<和哪个词最容易混，一句话说明区别；没有写「无」>
@@@
```

## 五、想 · 内化型（日志 18 篇），已有成熟做法

这一类不靠批量提示词，靠逐日人工加模型协作。已有的固定做法，成稿见 `日志/2026-08-04.md`：

```
你是我的日志整理助手。这一步是日志的深度整合，不是排版。

对我给的这一天（含若干条"视频收藏"与"随笔"），完成：

1. 每条收藏：标题用【原视频标题】（去掉"_哔哩哔哩_bilibili"与内联话题标签），
   正文重写为自然叙述——保留我的观点与情绪，但补上"不补就读不懂"的背景、
   把指代交代清楚（"它""这个东西"必须说清是什么）。
2. 随笔条目：标题写成「随笔 · 简述」，正文保持原话，只做必要的断句与错字修整。
3. 跨条目关联：如果这一天有几条在讲同一件事，在最后一条里点一句它们的共性。
4. 标签：原有标签一个不动，在**同一行**追加新提炼的短语（无前缀）。

【禁止】不要写"这是给将来的我看的"之类元叙述；
        不要用"这是什么/我的判断"这类小标题；
        不要抒情，不要替我拔高。

范围：严格等于我原文件里现有的条目数，不要去别处补条目。
```

校验每次必跑：原标签种类数、BV 号、图片引用三项 0 丢失；元叙述 0 处、层级前缀 0 处。

## 六、审查型（用来看模型产出对不对，不产出内容）

```
下面是我让模型给一批笔记生成的"追加块"。请当审查员，逐条检查：

1. 【结论/问题】是否脱离了原文也能读懂？有没有出现"讲了一个关于 X 的视频"这种空壳？
2. 有没有编造原文里没有的信息？
3. 有没有出现我不允许的写法：元叙述（"这条笔记是为了…"）、
   层级前缀（"内核/…"）、评价性空话（"很不错""值得学习"）？
4. 有没有把原文的克制观点改写成更强的断言？

输出：逐条列问题，只列有问题的；全对的写「通过」。
不要重写内容，只指问题。
```

## 七、参数建议

| 项 | 值 | 理由 |
|---|---|---|
| 每批条数 | 10 | 约 2.5 万字，稳定不丢条 |
| 分批依据 | 按领域目录 | 同领域上下文一致，总结质量更高 |
| 温度 | 低（0.3 左右） | 这是结构化任务，不需要发挥 |
| 一次只跑一型 | 是 | 混合类型会让模型输出格式漂移 |
| 幂等标记 | frontmatter `整理: <日期>` | 防重复追加，可查进度 |

每批跑完的硬标准：

- 追加块条数等于输入条数，不能有漏条
- 原 Tags 行、BV 号、图片引用三项 0 丢失
- 追加块里没有元叙述、层级前缀、空话

跑偏就停，改提示词重跑这一批，不要带着错误样本往下推。
