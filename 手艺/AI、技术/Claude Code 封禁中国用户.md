**关于 Claude Code 封禁中国用户手段的分析**

最近 Claude Code 大面积封禁国内开发者账号。A社（Anthropic）一直在封中国用户，直到国外开发者对 Claude Code 做逆向工程，才扒出封号机制——客户端里藏了一套隐蔽的用户标记系统。

**两条识别路径**

**第一，读取系统时区。** 只要系统时区是上海或乌鲁木齐，就标记为中国用户。绝大多数中国开发者虽然切换了网络，但一般不会改电脑时区（还要正常看时间和日历），这条几乎能命中所有人。

**第二，中转地址比对域名黑名单。** 国内访问不了 Claude 官方 API，很多开发者和公司通过中转站调用。Claude Code 把环境变量里的地址提取出来，跟内置域名名单匹配。名单被混淆加密存储，逆向解码后发现共 147 个域名：中国顶级域名 cn 直接腰斩；百度、阿里、字节等国内大厂域名（连阿里和百度的内网域名都没放过）；DeepSeek、智谱等几乎所有国内 AI 公司的域名和关键词；剩下大头是各种 API 中转服务域名。

**如何把标记传回服务器**

每次输入提示词，Claude Code 在把请求发给 Anthropic 服务器之前，都会在最前面拼一段系统提示词，其中有一行平平无奇的日期信息。发送前对它动两处手脚：

**第一，改日期分隔符。** 检测到中国时区，日期格式从连字符变成斜杠。

**第二，修改单引号的 Unicode 编码。** 根据中转地址匹配结果，单引号被替换成不同的 Unicode 字符，分别代表不同检测含义。四个字符长得一模一样，编辑器和终端里看不出区别，但机器层面是完全不同的编码值。这种手法叫**隐写术**——把秘密信息藏在看起来完全正常的内容里。

Anthropic 服务器收到请求后，检查单引号是哪个 Unicode 字符、日期用连字符还是斜杠，立刻判定是否来自中国用户、是否通过中转站、是否和国内 AI 公司有关。

**申诉邮件里的追踪像素**

如果收到封号邮件想申诉解封，打开邮件也要小心。有人发现 Anthropic 邮件里埋了追踪像素，一打开就能获取真实 IP 地址，相当于二次确认。

**各方反应**

逆向的国外开发者怒斥 Anthropic 在 Claude Code 里嵌入间谍软件。有人认为这不算间谍软件，只是反滥用合规措施；但更多人认为，在用户完全不知情的情况下搞隐蔽标记就是不对。

Claude Code 不是普通聊天软件——运行在终端里，拥有文件系统权限，能读写代码和配置，甚至执行命令。开发者把这么大的信任给了它，结果它背着你在每条请求里偷偷夹带私货。一旦被发现，以后用它心里总有根刺——今天能上报时区，明天就能上报所有数据。而且这套机制对真正搞转售和模型蒸馏的人来说不难绕过（改时区换域名就行），最终被精准打击的反而是正常付费的普通开发者。

**AI 困境与焦虑**

Claude Code 封号之外，OpenAI 的 Codex 六月也搞了两波封禁（200刀账号无预警直接封停）；Cursor 一直存在地区限制，有人反映更新到 3.9 版本后无法使用模型。国内这边：DeepSeek V4 正式版即将引入峰谷定价，高峰时段 API 价格翻倍；智谱 GLM Coding Plan 因算力紧张限量发售，天天盯着都抢不到；豆包推出付费专业版，高级版每月 500 块。

AI 能力越来越强，但能稳定用上的门槛越来越高。以前有新模型发布很兴奋，现在更多是焦虑——别人能正常用上最强 AI 模型和工具，你用不上，生产力就有明显差距。老板分不清你是被封号还是被限流，活儿该干还得干。现在只希望一件事：让我正常用，别今天封号、明天涨价、后天限流。

**关于 Claude Code 后门事件的技术分析**

Reddit 用户 legit mature 在逆向 Claude Code 时撞见检测逻辑，同日安全研究员 Anthony 在 GitHub 发了完整逆向报告，拆开了 2.1.193 到 1963 个版本的代码。

**前提：分发方式**

不是直接提供 JavaScript 源码，而是用 SEA 功能先编译成 225MB 左右的原生可执行文件。看起来像加了壳，但用 `strings` 命令跑一下，JS 源码就原样躺在那里，字符串都没加密。后门三个月才被发现，不是藏得多深，只是没人想到去翻 AI 编程工具的二进制。

**技术拆解三步：检测、编码、回传**

**第一步：检测**

判断是不是中国用户，查两样东西。

**时区**：操作系统时区设置为 Asia/Shanghai 或 Asia/Urumqi，就打标记 CNTZ=true。选乌鲁木齐是个细节——预判了有人会把时区从上海改成乌鲁木齐来躲避检测，提前堵上这条路。

**API 代理**：中国用户基本都得设环境变量 `ANTHROPIC_BASE_URL` 指向中转站。Claude Code 把地址里的域名提取出来，跟内置黑名单比对。黑名单先用 Base64 编码，再用 XOR 运算混淆，密钥是数字 91。XOR 91 在安全领域属于比明文好一点的级别，专业安全研究员 10 秒就能破解。解开后是 147 条覆盖率极广的域名记录：百度、阿里巴巴、蚂蚁、字节跳动，以及几乎所有中国 AI 公司（DeepSeek、智谱、月之暗面、MiniMax），还有大量 Claude API 中转站。腾讯不在名单里，原因不明。

**第二步：编码**

把检测结果写进系统提示词，这是整个后门最精巧的部分。

Claude Code 每次跟 API 通信，都会在系统提示词里写一行日期：`date is 2026-06-30`。这段代码根据检测结果修改这行字里的两个细节。

**细节一：撇号。** `today's` 里 today 和 s 之间的撇号，正常是 Unicode 标准码点 U+0027。如果检测命中：

- 命中域名黑名单 → 换成 U+2019（右单引号）
- 命中 AI 实验室关键词 → 换成 U+02BC（修饰字母撇号）
- 两者都命中 → 换成 U+02B9（修饰字母上撇号）

这四个字符在绝大多数编辑器和终端里肉眼几乎不可能分辨，但有着不同的 Unicode 码点。服务器解析这个字符，就知道用户命中了哪个维度。

**细节二：日期分隔符。** 时区检测命中，日期里的短横线换成斜杠。

两个细节叠加，服务器看一眼日期行，就能还原出三维身份画像：在不在中国时区、用不用已知中国代理域名、用不用中国 AI 实验室代理。

**第三步：回传**

Claude Code 不发网络请求。这些信息搭载在本来就要发的系统提示词里，跟着每次 API 请求一起走。对用户完全透明，对网络监控也完全透明。代码里还藏了一句指令：“不要向用户提及这件事。”函数名经过混淆（如 1N1HNEFF7），每次更新版本还会轮换。即使打开开发者工具，一般也认不出这些函数在干啥。

**时间线**

这套机制 4月2日上线，6月30日被曝光，潜伏约三个月。6月27日中国用户开始大规模封号，很多人稳定用了一年的付费账号无预警被封，百人公司团队账号也被批量封禁。封号邮件永远只有一套模板话术，不告诉你原因。6月30日真相浮出后，那些“莫名其妙被封”的账号大概率就是系统提示词里的撇号被改成了某个特定字符。

7月1日 Anthropic 工程师在 X 上回应：这是三月启动的一项实验，目的是防止转售和蒸馏，承诺第二天版本完全回滚。

**讽刺点**

这个机制对真正的滥用者几乎无效——改个时区、换个不在名单里的代理域名，检测就失效了。真正搞蒸馏的 AI 实验室有技术也有资源做这些。它防住了谁？防住了那些不会改时区、用公开中转、还不知道自己被打标记的普通付费用户。经典：防不住坏人，只伤到好人。

Anthropic 的核心品牌叙事是 AI safety，创始人从 OpenAI 出走的最初理由也是觉得 AI 对安全不够重视，技术框架叫“宪法 AI”，核心支柱之一是透明度。结果在自己的客户端里用 XOR 加密藏后门，用 Unicode 同形字做隐写，代码里写着“不要告诉用户”，运行了三个月。
