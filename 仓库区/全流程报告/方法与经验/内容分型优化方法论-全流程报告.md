# 内容分型优化方法论

> 面向：MyDigitalBrain 全库 447 篇内容笔记
> 问题：「所有内容我还要从头回看一遍，面对不同的对象该怎么对照优化？量不小，而且光记不是目的。」

---

## 一、先把问题拆准

你的问题里有两层，得分开答。

**第一层「不同的对象」** —— 我理解是库内**不同类型的笔记对象**（视频消化记录 / 操作教程 / 日志 / 读书笔记 / 词表 / 报告）。如果你指的是别的意思，第七节单列了两种可能。

**第二层「光记不是目的」** —— 这句是关键。它在说：笔记的价值不在"存下来了"，在"能被调用"。所以：

> **优化的方向不该按主题分（军事 / 健康 / 科技），该按「这篇将来怎么被调用」分。**

同一篇讲"睡眠"的内容——如果将来是用来**查**的，就该压成结论；如果是用来**做**的（"怎么改善睡眠环境"），就该写成可执行步骤。主题一样，优化方式完全不同。

---

## 二、四类调用 → 四套标准

| 调用方式 | 对象 | 篇数 | 现在是什么 | 优化目标 |
|---|---|---|---|---|
| **查** | `仓库区/知识/`（视频消化记录） | 300 | 我看过的内容 | 看过 → **能判断、能引用** |
| **做** | `仓库区/手艺/`（教程 / 踩坑） | 87 | 我抄下的步骤 | 抄了 → **试过、知道何时会失效** |
| **想** | `仓库区/日志`·`旧日志`·随笔 | 18 | 时间流水 | 流水 → **可回溯的档案** |
| **练** | 书 · 语言 · 提示词 · 模板 | 20 | 学习材料 | 材料 → **可复习的系统** |
| — | 军师台账、31 个索引 | 33 | 活的状态文件 | **只维护，不优化** |

### ① 查 · 认知型（300 篇，`仓库区/知识/`）

**现在长这样**

```
[视频原标题_哔哩哔哩_bilibili](https://...?spm_id_from=...)
刷到一个FPV无人机视角的视频。画面里，两个俄罗斯士兵偶遇一架躲在草丛里的
FPV无人机。从他们后退拉枪栓的动作来看，是想远离并击毁它……
Tags: #FPV无人机 #战争 #绝望 #人性 #瞬间
```

一段第一人称叙述，读的时候是"我在讲我看到的事"。**问题**：半年后你只记得"我看过个无人机视频"，想不起当时得出什么判断——要重新读 2000 字。300 篇就是这么堆成 60 万字的。

**优化动作**（追加在末尾，原文不动）

- **一句结论** —— 脱离原视频也能读懂的陈述句
- **触发场景** —— 1–3 个"当我在做 X 时会用到它"
- **补漏** —— 需要背景才读得懂的地方、明显笔误

**验收标准**

- [ ] 结论是**陈述句**（不是"这是讲 XX 的视频"）
- [ ] 触发场景**具体到动作**（不是"增长见识"）
- [ ] 原有 BV 号 / 图片引用 / Tags 行 **0 丢失**

**演示**（就用上面那张卡）

```
> 结论：真正的绝望不是喊叫，是身体先反应、表情还没来得及跟上。
> 会用上：写人物濒死的段落 / 分辨"表演性恐惧"和真实恐惧 / 分析战场影像
> 补漏：FPV 是"穿越机"第一人称视角，画面抖动大、速度快——最后那帧定格
        是偶然拍到的，不是刻意给的特写。
```

### ② 做 · 执行型（87 篇，`仓库区/手艺/`）

**现在长这样**：分点的工具 / 步骤清单，带命令。例如 `npx skills add alchaincyf/huashu-design`。

**问题**：这类内容**会过期**。半年后按钮位置改了、命令参数变了、软件下架了——你还照着做，白折腾。而笔记里**没有任何"我验证过没有 / 什么时候可能失效"的信息**。

**优化动作**

- **前置条件** —— 执行前需要什么（版本、权限、账号、系统）
- **失效信号** —— 这类操作最容易随时间消失的点
- **验证状态** —— 试过没有、成败、日期

**验收标准**

- [ ] 有明确的「前置条件」行（原文没写就标"原文未写"）
- [ ] 标出至少 1 个「最可能失效的地方」
- [ ] 命令 / 代码块 **0 丢失**

> 这一类**值钱且数量少**：87 篇，但每失效一条就是一次真实的返工。

### ③ 想 · 内化型（18 篇）

**已有成熟做法**（2026-08-03 / 08-04 已验证）：深度整合成"可回溯档案"。

**标准**：补背景、消除指代依赖、跨条目关联、保留原观点与情绪；**不加元叙述、不加解释性小标题、不加层级前缀**。

这一类**继续逐日推进**即可，不必等新方案。

### ④ 练 · 重复型（20 篇）

对象：`工作区/书/《苏菲的世界》`（4）、`工作区/语言/道本语/词汇`（1）、`仓库区/手艺/学习提示词`（8）、模板等。

**性质**：跟①③根本不同——它们不是"要能查到"，是**要能记住**。记忆靠重复，不靠检索。

**优化动作**

- **提问化** —— 把条目转成能自问的问题（答案就在库里）
- **复习标记** —— frontmatter 加复习状态与下次复习日期
- **记忆锚点** —— 词表这类，给每个词绑一个画面或例句

**验收标准**

- [ ] 每个条目都能问出一个问题
- [ ] 词表词条有例句或锚点
- [ ] 复习状态字段可被检索

### ⑤ 状态文件（33 篇）—— 不要优化

`工作区/军师/进度台账.md`（唯一状态源）与 31 个索引页，是**生成物或指针**。优化它们 = 破坏它们。索引永远是"重跑脚本"，不是"编辑内容"。

---

## 三、关键：把"回看 447 篇"变成"审 447 条"

这是解决"量不小"的钥匙。

**不要**把优化理解成"再读一遍、再写一遍"——那是 2.2 MB 文本。

**要**让模型做**压缩**，产出你只需要**审**的东西：

| | 现在 | 优化后 |
|---|---|---|
| 回看一篇要读 | 约 2000 字叙述 | 约 60 字（结论 + 场景） |
| 全库回看总量 | 约 90 万字 | **约 3 万字** |
| 通读一遍 | 几十小时 | **2–3 小时** |

也就是说，"从头回看"这件事的**操作方式要变**——不是打开 300 个文件逐个读，是**先让模型压成 300 条，你只审这 300 条**。你的判断力花在"这条总结对不对、要不要留"上，而不是花在重读上。

这也是为什么下面的流水线设计成「模型写前半段、你审后半段」。

---

## 四、流水线（怎么借助大模型）

```
① 分批    每批 10 篇（约 2.5 万字），按「领域」切，不跨领域混批
            ↓
② 提示词  按类型选（见《优化提示词包》），一次只跑一种类型
            ↓
③ 产出    模型只输出「结构化追加块」，不重写原文
            ↓
④ 校验    脚本比对：原标签种类 / BV 号 / 图片引用 三项 0 丢失
            ↓
⑤ 追加    程序化写入笔记末尾；frontmatter 加「整理: <日期>」作幂等标记
            ↓
⑥ 抽检    每批人工看 2 篇；跑偏就停，改提示词重跑
            ↓
⑦ 提交    每批一次 git commit，坏了能回退
```

**几个设计要点**

- **幂等** —— frontmatter 加 `整理: 2026-10-16`。重复跑不会重复追加；也能用搜索 `["整理":` 查出已处理 / 未处理。
- **不删不改** —— 所有产出都是**追加块**。原文永远在，写错了就是删掉那个块。
- **按领域分批** —— 同领域一起处理，模型吃得到上下文（"这几张是同一主题"），总结质量更高。
- **先小后大** —— 先用**一个领域 9–12 篇**跑样板，格式确认后再全量。不要一上来就 300 篇。

## 五、顺序（按 ROI 排）

| 序 | 做什么 | 篇数 | 为什么是这个顺序 |
|---|---|---|---|
| **1** | 执行型（手艺 87） | 87 | 最少、最值钱。教程过期 = 真实返工，做完立刻能用 |
| **2** | 认知型（知识 300） | 300 | 量最大，收益是复利的（每次检索都省时间）。排第二是因为要先用第 1 类练手、定格式 |
| **3** | 内化型（日志 18） | 18 | 已有成熟做法，保持逐日节奏，不必挤 |
| **4** | 产出型（报告 37） | 37 | 抽「可复用方法」，量小 |
| **5** | 重复型（书 / 语言 / 提示词 20） | 20 | 要先设计复习机制，最后做 |

**先做一个样板**：建议挑 `仓库区/手艺/` 里某个子目录（比如「浏览器与网络」9 篇），跑完看效果、定格式，再推全量。

---

## 六、红线（不管哪一型都别踩）

1. **不改原文** —— 只追加
2. **不写元叙述** —— 不出现"这条笔记是为了…""将来我失忆了…"之类
3. **不加层级前缀** —— 标签就直接写短语，不写 `内核/xxx`
4. **每批必校验** —— 标签种类 / BV 号 / 图片引用 0 丢失
5. **每批必提交** —— 一次 git commit，坏了好回退
6. **不碰状态文件** —— 军师台账与索引页只读不写

---

## 七、如果你说的"不同对象"是别的意思

**若指「不同受众」** —— 同一份内容要给不同人看（自己 / 别人 / 公开）：那要做的是**分版**而不是分型。做法是同一笔记加"详版 / 摘要版"，或用折叠块把"给自己看的"与"能给外人看的"分开。目前你的库几乎全是给自己看的，暂时用不上。

**若指「不同来源」** —— 视频 / 书 / 文章 / 自己写的：这个维度**已经在用了**（类型标签：知识卡片 301 / 教程 63 / 报告 28 / 日记 13…）。它决定"放哪"，但**不决定"怎么优化"**。真正决定优化方式的是第二节的**调用方式**。
