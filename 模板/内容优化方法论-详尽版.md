# 内容优化方法论 · 详尽版

要照着做的时候看这份。每个动作都有标准、有模板、有验收，文末的例子是真跑过的。
只想记个大概，看 [[内容优化方法论-概括版]]。为什么这么分，推导在 [[内容分型优化方法论-全流程报告]]。
校验脚本在同一目录，`模板/verify_append.py`。

## 一、什么时候用

### 三个条件

- 内容是我自己写的。有自己的观察和判断，才有东西可提炼。纯剪藏、转载别人的原文，不算
- 已经有正文。至少有一段成形的叙述，或者几个步骤。只有一个链接、只有一张图的，不算
- 将来会被用到。会被查、被做、被想、被练里的某一种用到。存着只为"以后可能有用"的，其实永远不会打开

### 拿到一篇笔记，怎么判断

```
是索引页、台账、库首页吗？
  是 → 停。这些是脚本生成的，只维护不优化，改了下次重跑就没了
  否 → 有正文吗？
        没有 → 标「不足」，跳过。别硬优化空壳
        有 → 正文是什么性质？
              看过一件事之后的感想、复述  → 查型（仓库区/知识）
              要照着做的步骤、工具、命令  → 做型（仓库区/手艺）
              我这一天的记录              → 想型（日志、随笔）
              要背要记的材料              → 练型（书、语言、提示词）
              我做过的项目复盘            → 报告型（全流程报告）
```

### 五型分别是什么样

查型，也叫认知型。看完视频或者文章，用自己的话记下来的内容笔记。特征是第一人称，"刷到一个…""画面里…"，结尾一句自己的判断。前提是正文里至少有一个能提炼的判断，全是描述没有判断的就跳过。仓库区/知识里有 300 篇。

做型，也叫执行型。教程、工具清单、踩坑记录、配置步骤。特征是分点，带命令、路径、网址，有第一步第二步。前提是内容指向一个能动手做的动作。仓库区/手艺里 87 篇。这一类特殊在哪：它会过期。半年后按钮改了、服务下架了，照着做就是返工。

想型，也叫内化型。日志、随笔。以日期为单位，多条并列，时间流水。前提是里面有我当时的想法，不只是流水账。日志 12 篇，旧日志 4 篇，随笔 2 篇。这一类不用批量提示词，逐日人工加模型一起做，做法已经定了。

练型，也叫重复型。读书笔记、词表、提示词集。条目化，将来要复习而不是检索。前提是条目能转成问题。书 4 篇、语言 1 篇、提示词 8 篇，加上模板大约 20 篇。这类靠重复不靠检索，所以要加的是复习机制，不是检索字段。

报告型，也叫产出型。项目全流程报告，37 篇。要做的是抽出可复用的方法和踩过的坑。

### 这些不动

- 三十来个 `X 索引.md`，脚本生成的，重跑就覆盖
- `工作区/军师/进度台账.md`，唯一的状态源，是活文件
- `库首页.md`、`图片索引.md`，也是生成的
- `仓库区/图片、附件/` 里 432 张图，已经在正文被引用过了，一张张认价值不大
- 0 字节或者只有链接的笔记，没有东西可提炼

边界就一句：将来会被查、被做、被想、被练里的某一种调用，就适用；永远只是存着，就不适用。

## 二、为什么这么分

说白了就一句：「光记不是目的」怎么落地。

优化的方向不按主题分（军事、健康、科技），按这篇将来怎么被调用分。

为什么主题不算分型依据？因为主题只决定它放哪个文件夹，不决定怎么处理。

拿讲睡眠的内容举例：

- 拿去查（人为什么需要深睡），压成一句结论加场景就够了。我要的是判断，不是过程
- 拿去做（怎么改善睡眠环境），就写前置条件和失效风险。我要的是能照着做，还知道什么时候不管用
- 拿去想（我那天为什么失眠），保留原话和情绪。我要的是能回到当时的自己
- 拿去练（睡眠分几个阶段），写成问题加答案加锚点。我要的是能背下来

同一件事，四种处理。所以领域标签管"在哪"，调用方式管"怎么办"，两样都得有。

### 为什么是往后加，不是重写

三个原因。

一是能回退。原文永远在，加错了把那个块删掉就行。
二是能验收。加的东西是新增的，脚本能证明原文一个字没丢。
三是能分批。300 篇不用一次做完，做一半停下来，库也是完好的。

重写一样都做不到。

## 三、五型怎么做

### 查型

正文一般长这样：

```
[视频标题_哔哩哔哩_bilibili](https://...?spm_id_from=...)
刷到一个FPV无人机视角的视频。
画面里，两个俄罗斯士兵偶遇一架躲在草丛里的FPV无人机……
Tags: #FPV无人机 #战争 #绝望 #人性 #瞬间
```

毛病在哪：半年后只记得"我看过个无人机视频"，想不起当时得出什么判断，得重读 300 字。300 篇堆起来就是 60 万字。

追加块模板：

```
@@@ <文件名>
结论：<一句话陈述句>
场景：<我在做什么的时候会用上> / <另一个场景>
补漏：<补什么 或 无>
@@@
```

三项分别要什么标准。

结论得是判断，不是介绍。好的像"真正的绝望不是喊叫，是身体先反应、表情还没来得及跟上"。写成"讲了一个关于战争的视频"就是空壳，写成"我们要珍惜和平"是把话拔高成鸡汤。

场景得具体到动作，比如"写人物濒死的段落"。写成"增长见识"就是空话。

补漏是补原文没交代清楚、可不知道就影响理解的东西。像"FPV 是穿越机第一人称视角，画面抖动大"，几句话说清就行。补成一大段背景介绍就喧宾夺主了。

验收三条：结论是陈述句，脱离原视频也能读懂；场景具体到动作；原来的 BV 号、图片引用、Tags 行一样没丢。

### 做型

正文一般是这样：分点的工具、步骤、命令，带网址或者代码。

毛病在哪：这类内容会过期。半年后按钮位置改了、命令参数变了，你还照着做，白折腾。可笔记里没有任何"我验证过没有、什么时候可能失效"的信息。

追加块模板：

```
@@@ <文件名>
解决什么：<一句话>
前置条件：<软件版本、账号、权限、系统环境；原文没写就写「原文未写」>
失效风险：<最可能随时间失效的地方，至少一条>
验证状态：<已验证 <日期> / 未验证>
@@@
```

四项分别要什么标准。

"解决什么"一句话说清，别复述目录。像"用脚本给常用网站打补丁，去掉广告弹窗、自动翻页"。

"前置条件"写照着做之前得有啥，比如"浏览器已装脚本管理器；访问源站需 VPN"。原文没写就写「原文未写」，别替它猜一个填上。

"失效风险"至少一条，而且要点到具体的机制，比如"源站国内需 VPN，一旦被墙，这篇列的脚本就都装不上"。

"验证状态"别美化。原文里没有用过的痕迹，就写"未验证"。

验收三条：有明确的前置条件；至少一个最可能失效的地方；命令、代码块、网址一样没丢。

### 想型

不做批量提示词。逐日推进，格式见 [[2026-08-04]]，那是一份成稿样板。

标准是：补背景、把指代补全、把跨条目的关联写出来，同时保留原来的观点和情绪。不加元叙述，不加解释性的小标题，不加层级前缀。

范围上有个硬规矩：严格按那个 .md 文件里现有的条目数来，不去 git 历史、不去别的目录补"这一天原本还有几条"。

### 练型

追加块模板：

```
@@@ <文件名>
问题：<能拿来考自己的问题>
答案要点：<三句以内>
锚点：<一个画面、比喻或者例句>
@@@
```

要是词表，用这个：

```
@@@ <词>
词义：<不超过 15 字>
例句：<造一个简单例句>
易混：<最容易和哪个词混；没有就写「无」>
@@@
```

验收两条：每个条目都能问出一个问题；词条有例句或者锚点。

这一类还多一步，在 frontmatter 里加复习字段，让"该复习了"能被找出来：

```yaml
复习: 未开始        # 未开始 / 进行中 / 已掌握
下次复习: 2026-10-23
```

### 报告型

```
@@@ <文件名>
可复用方法：
1. ...
2. ...
踩过的坑：<真正走了弯路的点>
可省掉：<事后看多余的步骤>
可提前：<应该更早开始的步骤>
@@@
```

要求一条：脱离这个项目也成立，把项目里的专有名词换成通用的说法。

## 四、七步怎么走

```
① 分批 ──▶ ② 选提示词 ──▶ ③ 出追加块 ──▶ ④ 校验
                                              │
                            ⑦ 提交 ◀── ⑥ 抽检 ◀── ⑤ 追加
```

第一步，分批。每批 10 篇，大概 2.5 万字，这个量稳定，不容易丢条。按领域切，不跨领域混批，同一个领域上下文一致，模型总结得更好。先拿一个领域 9 到 12 篇做样板，格式确认了再全量。

第二步，选提示词。一次只跑一种类型。混着跑格式会飘。提示词在 [[笔记内容优化-提示词包]]。

第三步，出追加块。模型只输出结构化的块，不重写原文。用 `@@@ <文件名>` 分隔，方便程序解析。

第四步，校验。这一步不能跳。

```bash
python 模板/verify_append.py <原文件> <写入后的文件>
```

它比对三样、自查两样：内联 Tags 的标签种类不能丢，BV 号不能丢，图片引用不能丢；元叙述（"这条笔记是为了…""失忆"这类）不能有，层级前缀（`#内核/xxx`）不能有。

这里有个真实的坑：全库有 39 篇笔记的 `Tags:` 行折成了两行，比如 `油猴插件.md` 里 `Tags: … #网页加速` 换行 `#看图工具 #比价`。校验脚本得把续行一起读进去，不然这 39 篇的标签会漏检，丢了也报 OK。`verify_append.py` 已经处理了。

第五步，追加。写到笔记末尾，同时在 frontmatter 里加个标记：

```yaml
整理: 2026-10-16
```

这样重复跑不会重复追加，也能用搜索 `["整理": 2026-10-16]` 查进度。

第六步，抽检。每批自己看两篇，看三件事：结论有没有拔高、场景是不是空话、有没有编造原文没有的信息。跑偏了就停下来，改提示词重跑这一批，别带着错误样本往下推。

第七步，提交。每批提交一次：

```bash
cd /d/Obsidian/Documents/MyDigitalBrain
git add -A
git commit -m "优化(做型)：浏览器与网络 9 篇追加块"
```

坏了一个 `git reset --hard <上一批>` 就回来了。

## 五、参数

- 每批 10 条，大概 2.5 万字，稳定不丢条
- 按领域目录分批，同领域上下文一致
- 温度调低，0.3 左右，结构化任务不需要发挥
- 一次只跑一型，混型格式会飘
- 幂等标记写在 frontmatter 的 `整理: <日期>`

这个文件夹里的工具只有一个：`verify_append.py`，追加块校验。正例通过、反例报错都实测过。

## 六、出问题怎么办

漏条了（10 条只出 8 条）：批太大，或者模型截断。降到 5 篇一批，再看看输入有没有用 `===` 分隔。

结论写成"讲了一个关于 X 的视频"：提示词约束不够。在该型提示词里加一句"结论必须是判断句，不是内容介绍"。

冒出"这条笔记是为了…"：通用约束没带上。通用约束得每条提示词前面都加。

标签被擅自改了：模型越界。通用约束第一条已经禁止，校验脚本也能抓出来。

校验报标签丢失，可看着没丢：Tags 行折行被截断了。用本目录的 `verify_append.py`，它处理了续行，别自己写正则。

追加块跑到 frontmatter 里去了：写入位置判断错了。得写在正文末尾，也就是最后一行 `Tags:` 后面。

追加了两遍：没记幂等标记。先查 `["整理":` 再跑。

某一型怎么跑都不对：多半是型选错了。回上面那个判断流程复核一遍。

## 七、完整走一遍 · 做型

真拿一篇笔记走的七步，校验输出是真跑出来的。

### 第 0 步，选型

文件是 `仓库区/手艺/浏览器与网络/油猴插件.md`。

判断依据三条。位置在 `仓库区/手艺/`，指向做型。frontmatter 里写的 `类型/教程`，跟做型对得上。正文标题是「10 款油猴脚本的推荐整理」，里面有 4 个网址代码块加逐条工具说明，这就是要照着装的东西。

三个信号一致，定为做型。

### 第 1 步，分批

同一个目录一共 9 篇，先全量试跑：

```
仓库区/手艺/浏览器与网络/
  Edge 浏览器阻止不安全下载.md
  Edge浏览器插件.md
  Edge浏览器设置.md
  Via浏览器.md
  下载谷歌翻译音频.md
  互联网核心协议.md
  油猴插件.md
  解决edge浏览器显示"你尚未连接"的问题.md
  访问Github和HuggingFace工具.md
```

这里就有个边界问题：`互联网核心协议.md` 其实是协议原理知识，不是教程。分型不能只看目录，得看正文性质，这篇应该归到查型。这就是第 6 步抽检要抓的东西。

### 第 2 步，选提示词

通用约束加做型提示词，全文在 [[笔记内容优化-提示词包]]。

### 第 3 步，拼输入

```
【通用约束 · 必须遵守】
1. 绝对不改动我的原文。你只输出"追加块"，我会把它贴到笔记末尾。
2. 不要写元叙述：不出现"这条笔记""本记录""为将来""以备查阅"这类话。
3. 不要写解释性小标题。
4. 标签直接写短语本身，不要任何层级前缀（不写 内核/xxx、本质/xxx）。
5. 不要复述原文，不要加评价性的话。
6. 输出格式必须严格遵守我给的模板，用 @@@ 分隔每一条。
7. 如果某条信息不足以完成要求，就写「不足」，不要编造。

你是我的操作手册审核助手。读下面这批笔记（每批 10 条）。
它们是教程、工具清单、踩坑记录这类"要照着做"的内容。

对每一条，输出四项：
1. 解决什么 —— 一句话说清这条能解决什么问题。
2. 前置条件 —— 照着做之前需要具备什么（软件版本、账号、权限、系统环境、依赖项）。
   原文没写就写「原文未写」，不要替我猜一个填上。
3. 失效风险 —— 这条里最容易随时间失效的部分是什么。至少写 1 条。
4. 验证状态 —— 判断这条是否留下了"我试过"的痕迹。没有就写「未验证」。

输出格式：
@@@ <文件名>
解决什么：<一句话>
前置条件：<...>
失效风险：<...>
验证状态：<已验证 <日期> / 未验证>
@@@

注意：命令、代码、路径要原样引用，不要改写或补全。

=== 文件：仓库区/手艺/浏览器与网络/油猴插件.md
标题：油猴到底有多香？10个小众但效果拔群的优化"补丁"
正文：
**关于 10 款油猴脚本的推荐整理**
来源：Greasy Fork（国内最方便的脚本网站，需 VPN）。……
（此处为原文全文，含 4 个网址代码块）
Tags: #油猴脚本 #GreasyFork #浏览器插件 #网盘助手 #搜索引擎 #网页加速
#看图工具 #比价
===
```

### 第 4 步，模型给出的追加块

```
@@@ 仓库区/手艺/浏览器与网络/油猴插件.md
解决什么：用浏览器脚本给常用网站打补丁——去掉广告弹窗与登录墙、自动翻页、批量抓图、看历史价格。
前置条件：浏览器已装脚本管理器（Tampermonkey 类）；Greasy Fork 需 VPN 才能访问。
失效风险：源站 Greasy Fork 国内需 VPN，一旦被墙则这篇列的所有脚本都装不上；去广告/翻页类脚本依赖目标网站 DOM 结构，网站改版就会失灵，只能等作者更新。
验证状态：未验证（原文是清单，没有使用过的痕迹）。
@@@
```

### 第 5 步，校验

把原文复制成 `a.md`，追加块加到 `b.md`，然后跑：

```bash
python 模板/verify_append.py a.md b.md
```

真跑出来的输出：

```
标签     原   8 → 新   8   OK
BV 号   原   1 → 新   1   OK
图片引用   原   0 → 新   0   OK

元叙述      0 处
层级前缀     0 处

结果：通过 —— 内容零丢失、写法合规。
```

再拿脚本抓一回错。故意删掉一个标签 `#比价`，把首行改成元叙述，输出：

```
标签     原   8 → 新   7   丢失 1
        ✗ #比价
BV 号   原   1 → 新   1   OK
图片引用   原   0 → 新   0   OK

元叙述      1 处
层级前缀     0 处

结果：不通过（2 项问题），请修正后重跑。
```

两种都试过，才敢往库里写。

### 第 6 步，写进去之后
